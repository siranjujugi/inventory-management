System architecture

A small two-process web app. The browser handles presentation and derived UI state; the API filters and validates data held in server memory.

The browser and API run as separate local development servers. The backend loads the JSON files when its Python module starts; it does not query a database.

Data storage and boundaries

  • Seed dataInventory, orders, forecasts, backlog, spending, transactions, and purchase-order JSON files live in server/data/.
  • At startupserver/mock_data.py reads the files into module-level Python lists and values.
  • At runtimeFiltering and summaries run in Python against those in-memory objects; there is no database, cache, or message broker.
  • PersistenceIn-memory edits are lost on restart. The seed JSON files are the durable demo inputs.
  • External APIsNone are required for the core inventory, orders, dashboard, demand, backlog, spending, and report flows.
Demo boundary: client-side profile/auth is mocked, and the backend CORS policy currently allows all origins. Treat the app as a local demo, not a production deployment.

Components and API surface

Responsibilities are intentionally direct: views own page loading and display state, while the API module centralizes most HTTP calls.

Frontend shell

App.vue + Vue Router

Provides navigation, shared filters, profile/task UI, and the active route view. Routes are registered in main.js.

Shared state

Composables

useFilters shares reactive filters; useI18n handles locale and currency; useAuth provides mock profile state.

Pages

Views and components

Dashboard, Inventory, Orders, Demand, Spending, Backlog, and Reports present data with modals and custom chart UI.

Browser data access

client/src/api.js

Uses Axios at the fixed local API base URL. Reports.vue currently calls the report endpoints directly with Axios.

Backend

server/main.py

Defines REST handlers, shared filters, summary/report calculations, Pydantic models, and development CORS middleware.

/api/inventory/api/orders/api/dashboard/summary /api/demand/api/backlog/api/spending/*/api/reports/*
Data loading

mock_data.py + server/data

Loads static JSON into memory during backend startup. Endpoints return data or calculate filtered/aggregated results from it.

Implementation note: client/src/api.js also defines task and purchase-order requests, but matching handlers are not currently defined in server/main.py. Those calls are outside the working API surface shown above.
